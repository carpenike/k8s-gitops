# Grocy

Household food inventory ([grocy/grocy](https://github.com/grocy/grocy)):
stock, products, locations and units, read and written by people in the
browser and by the homelab-mcp `grocy_*` tools. It ran on Forge as
nixpkgs' `services.grocy` (`hosts/forge/services/grocy.nix` in
carpenike/nix-config). This is the move onto the cluster.

Manifests: `kubernetes/apps/grocy/`. The layout follows
[replog.md](replog.md); the cutover follows the copy steps in
[home-automation.md](home-automation.md).

## What Forge runs today

| | |
| --- | --- |
| Hostname | `grocy.holthome.net`, internal only (Caddy vhost, no Cloudflare tunnel) |
| Path | Caddy (TLS, PocketID policy `home`) to Grocy's own nginx on `127.0.0.1:9970`, PHP-FPM pool `phpfpm-grocy` |
| Login | caddy-security puts the PocketID email in `X-Token-User-Email`; `ReverseProxyAuthMiddleware` reads it and creates the user on first sight. `/api` bypasses the portal and is protected by `GROCY-API-KEY` |
| Data | `/var/lib/grocy` on ZFS `tank/services/grocy`: `grocy.db`, `storage/`, `plugins/`, `settingoverrides/`, `viewcache/`. `config.php` is `/etc/grocy/config.php`, generated by Nix, not on the dataset |
| Settings | `CURRENCY=USD`, `CULTURE=en_GB`, the rest Grocy's defaults |
| Version | nixpkgs pins 4.7.1; the running instance reported 4.6.0 on 2026-11-27 (`grocy_health`) |
| Backups | Sanoid and syncoid to nas-1, Restic daily |

Forge's `AUTH_CLASS` is `Grocy\Middleware\ReverseProxyAuthMiddleware`.
Grocy 4.7.0 moved the auth middleware to `Grocy\Middleware\Auth\…`
(changelog: "Authentication middleware was reorganized, review your
`AUTH_CLASS` setting"), so Forge's own Grocy stops loading the next time
Forge deploys a 4.7 build. The cluster uses the new name.

## What runs here

One replica, `Recreate`. Image `ghcr.io/linuxserver/grocy` `v4.7.1-ls352`,
pinned by digest. It is the only maintained Grocy image:
`grocy/grocy-docker` was archived in February 2026 and points to it. The
image starts as root under s6, chowns `/config` to `PUID:PGID` (1000) and
runs nginx and PHP-FPM as that user, so the namespace is Pod Security
`baseline` and the root filesystem is writable. Port 80.

PVC `grocy-config` (`ceph-block`, RWO, 5Gi) is the image's `/config`.
Grocy's data directory is `/config/data`: `grocy.db`, `storage/`,
`plugins/`, `viewcache/` and a `config.php` the image copies from
`config-dist.php` on first start. Settings come from the environment
(`GROCY_<SETTING>`; Grocy reads it when there is no
`data/settingoverrides/<SETTING>.txt`): `GROCY_CURRENCY`, `GROCY_CULTURE`,
`GROCY_AUTH_CLASS`, `GROCY_REVERSE_PROXY_AUTH_HEADER`.

Init container `wait-for-data` holds the pod until
`/config/data/grocy.db` exists. An empty start would make a new database
with user `admin`/`admin` and hide a copy that never happened. A deliberate
fresh install can skip it with `/config/.allow-empty`. A VolSync restore
brings `data/` back, so it is not needed for a restore.

## Login

Grocy needs to know who is signed in: chores, stock changes and API keys
belong to a person. Its only SSO is a trusted header. HTTPRoute `grocy` is
on `envoy-internal` only, with no auth label, and SecurityPolicy `grocy`
replaces the gateway policy for it:

1. `oidc`: the same Pocket ID client and scopes as `network/pocket-id`,
   from Secret `grocy-oidc` (ExternalSecret `grocy-oidc`, item
   `pocket-id-gateway`, no new item). Its cookies are `EG_GROCY_*`. The ID
   token is forwarded upstream in `X-Grocy-Id-Token`.
2. `jwt`: provider `pocket-id` checks that token against
   `https://id.${SECRET_DOMAIN}/.well-known/jwks.json` and the issuer, and
   writes its `email` claim into `X-Grocy-User`. In Envoy Gateway 1.9.3 the
   JWT filter runs after the OAuth2 filter. Envoy's `jwt_authn` removes a
   client-sent `X-Grocy-User` before it sets its own.

`GROCY_REVERSE_PROXY_AUTH_HEADER` is `X-Grocy-User`. The value is the
same PocketID email Caddy sent on Forge, so the copied users match and
nobody gets a second account.

Grocy trusts that header from whoever connects. The pod's
CiliumNetworkPolicy admits port 80 from `envoy-internal` and the
homelab-mcp pods only. Egress is cluster DNS only.

The callback is `https://grocy.${SECRET_DOMAIN}/oauth2/callback`, already
covered by the `envoy-gateway` client's `https://*.holthome.net/oauth2/callback`
([gateway-auth.md](../platform/gateway-auth.md)). Like Forge's `home` policy, the SecurityPolicy's `authorization` block
allows only a token whose `groups` claim holds `home`; any other Pocket ID
account is refused at the gateway.

Grocy gives a user it creates on first sight `DEFAULT_PERMISSIONS`, which
defaults to `ADMIN` (enough to create API keys). The HelmRelease sets
`GROCY_DEFAULT_PERMISSIONS: USERS_EDIT_SELF`, so a new household login
starts with only its own profile and an admin grants the rest in Grocy
(Manage users). From the environment the setting is a single permission
name. Users copied from Forge keep their permissions.

There is no `/api` bypass on the route. Forge's existed for the MCP tools,
which now call the Service directly. A phone app that uses an API key
from outside the cluster would need a rule like Alertmanager's example in
[gateway-auth.md](../platform/gateway-auth.md).

## Agents

homelab-mcp calls `http://grocy.grocy.svc.cluster.local/api`
(`HOMELAB_MCP_GROCY_BASE_URL`) with `GROCY-API-KEY`, which Grocy checks
before it looks for the identity header. The keys are rows in `grocy.db`,
so they come over with the copy: item `homelab-mcp` field `grocy_api_key`
and the per-user `grocy.ryan` and `grocy.steffi` in
`homelab-mcp-user-credentials` stay as they are. The homelab-mcp policy
allows egress to the grocy pods on 80 and no longer names
`grocy.${SECRET_DOMAIN}`. Every `grocy_*` tool (`grocy_health`,
`grocy_find_products`, `grocy_attention`, `grocy_stock_item`,
`grocy_ensure` and the rest) uses that one client.

## Cutover

Merging this PR repoints the MCP tools at the cluster. Do it in one
sitting, with Ryan's go, in this order. Grocy and its tools are down from
step 1 to step 4, a few minutes.

1. On Forge, stop Grocy and keep it stopped:

   ```sh
   sudo systemctl stop phpfpm-grocy
   sudo mkdir -p /run/systemd/system/phpfpm-grocy.service.d
   printf '[Unit]\nConditionPathExists=/nonexistent\n' | \
     sudo tee /run/systemd/system/phpfpm-grocy.service.d/99-cutover-block.conf
   sudo systemctl daemon-reload
   sudo zfs snapshot tank/services/grocy@pre-cluster
   ls -la /var/lib/grocy /var/lib/grocy/settingoverrides
   ```

   Anything in `settingoverrides/` wins over the environment here too; read
   it before copying.
2. Merge. The pod starts and waits in `wait-for-data`.
3. Copy into `/config/incoming`, then rename it to `/config/data`. The
   rename is what ends the wait, so the app never sees half a copy:

   ```sh
   POD=$(kubectl -n grocy get pod -l app.kubernetes.io/name=grocy -o name)
   kubectl -n grocy exec $POD -c wait-for-data -- mkdir -p /config/incoming
   ssh forge 'sudo tar -C /var/lib/grocy --exclude=./viewcache --exclude=./plugins -cf - .' \
     | kubectl -n grocy exec -i $POD -c wait-for-data -- tar -o -C /config/incoming -xf -
   kubectl -n grocy exec $POD -c wait-for-data -- ls -la /config/incoming
   kubectl -n grocy exec $POD -c wait-for-data -- mv /config/incoming /config/data
   ```

   `tar -o` leaves the files owned by root; the image chowns them on start.
   The listing shows `grocy.db` and `storage/`. `viewcache/` is rebuilt
   and `plugins/` comes from the image. On start the image copies its
   `config.php`, chowns `/config` to 1000 and Grocy migrates the database
   from 4.6.0 to 4.7.1.
4. Check `grocy_health` through homelab-mcp (expect 4.7.1), then
   `grocy_find_products` and `grocy_attention`, with the Home and Steffi
   connectors.
5. Point `grocy.${SECRET_DOMAIN}` at the cluster: remove Forge's router
   record for it, and mikrotik-dns publishes the route's A record to
   `envoy-internal`. Sign in in a browser as Ryan and as Steffi. Each
   should land on their existing account (Settings, Manage users shows no
   new user).
6. nix-config PR: disable `services.grocy` on Forge and keep the dataset,
   sanoid and Restic for the rollback week.

Rollback before step 5: point `HOMELAB_MCP_GROCY_BASE_URL` back at
`https://grocy.${SECRET_DOMAIN}/api` (and its toFQDNs entry), remove the
drop-in on Forge and start `phpfpm-grocy`. Forge's data is as it was at
step 1. After step 5, also put the router record back. After days in the
cluster, copy `/config/data/grocy.db` and `storage/` back first, or Forge
loses what changed since.

## Backup

VolSync `ReplicationSource` `grocy`, `copyMethod: Snapshot`
(`csi-ceph-block`), every 6 hours at minute 35, of the whole volume, to
restic path `<REPOSITORY_TEMPLATE>/grocy` (item `volsync-r2-template`, no
new field). Keep 7 daily and 4 weekly. The mover runs as 1000, the owner
after the image's chown.

To restore: scale to 0, restore onto `grocy-config`, scale to 1.

## Monitoring

Grocy has no metrics endpoint. `GrocyDown` (kube-state-metrics) fires when
the Deployment should run and has had no ready pod for 15 minutes. That
includes a pod still waiting for the copy.
