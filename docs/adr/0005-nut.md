# In-cluster NUT, one upsd per sled

## Context and Problem Statement

The sleds have to shut down when the APC UPS is on battery and low, or
when it raises FSD. A first draft made Forge the NUT server. Forge is
one machine. If it is down, none of the sleds hear the UPS.

The APC network card is at `10.9.18.245`. Ryan confirmed the sleds can
reach `10.9.18.0/24`. The chassis has no need for Forge to be in that
path.

## Decision Drivers

- A sled must learn UPS state without Forge being up
- The same upsmon password is used by Talos and by `upsd`, and it is not
  plaintext in git
- Shutdown is the stock `upsmon` reaction to LB or FSD
- Power-on after the battery recovers stays on Forge, over IPMI

## Considered Options

- Forge runs `upsd`, every sled is a secondary of that server
- One `upsd` DaemonSet on every sled, `snmp-ups` to the APC card, Talos
  `upsmon` on `127.0.0.1`

## Decision Outcome

Chosen option: "one `upsd` per sled", because the poller then fails only
when that sled fails, not when Forge fails.

`nut-upsd` is a DaemonSet on all four nodes, control planes included,
host network, tolerating every taint. The image is
`docker.io/instantlinux/nut-upsd:2.8.5-r1`. `snmp-ups` polls
`10.9.18.245`. The UPS name is `apc`. `upsd` listens on `127.0.0.1:3493`
only, so the monitor password is not on the LAN. The Talos `nut-client`
extension uses the host network namespace, so that address is the host
loopback.

Each `upsmon` is a secondary of `apc@127.0.0.1` with user `upsmon`. On
LB or FSD it runs `SHUTDOWNCMD "/sbin/poweroff"`. Nothing waits for
another node. The four sleds power off independently. Forge is not a
client of these servers. Forge's own shutdown, if it has one, is
Forge's config.

The password is random and stored once in
`kubernetes/apps/nut-system/nut/app/secret.sops.yaml`, encrypted to the
age recipient and the YubiKey. Flux decrypts it for the DaemonSet.
`topf` reads the same key through a vals `ref+sops` in `talos/topf.yaml`.
The SNMP community is the other key in that secret. The card answers
SNMP v2c.

Until the DaemonSet is up, `upsmon` retries. The nodes still boot. That
gap is accepted.

### Consequences

- Good, because UPS shutdown does not depend on Forge
- Good, because the password exists in one ciphertext
- Bad, because a wrong SNMP community crashloops `upsd`, and `upsmon`
  then has nothing local to poll until it is fixed
- Bad, because the sleds do not shut down in a chosen order. etcd and
  the worker stop when each host sees LB or FSD

## Pros and Cons of the Options

### Forge as the NUT server

- Good, because one server is easy to describe
- Bad, because every sled is blind when Forge is down
- Bad, because it was a nix-config change that did not exist yet

### upsd on every sled

- Good, because each host polls the card itself
- Good, because `127.0.0.1` keeps the monitor user off the network
- Bad, because four drivers poll one card
